# 英作文タブ

「過去問」の右に「英作文」を追加。初期の一覧は FY25B → FY25A の2問です。
FY26Aは「使い方」と過去問の既存入口、FY26Bは試験完了後の既存入口を維持します。
共有Engine・UI・添削クライアントは変更せず、学校固有のHubを追加しています。

## 提出と履歴

- 下書きは既存の `writingDrafts`（FY26Aは `writingPractice`）を使用。
- 成功した添削ごとに UUID、問題キー、練習モード、送信時刻、答案、添削結果、型・模範解答の版を追記。
- 通信失敗・不正なAI応答は成功履歴に追加しません。二重送信を抑止。
- 送信中の編集は保持し、取得結果を送信した元の答案に関連付けます。
- 20回の上限による自動削除を廃止。今ある旧履歴は継承し、すでに削除済みの履歴は復元しません。
- バックアップに全履歴を含めます。統合時は提出IDで和集合、旧形式は答案・日時・添削内容で識別し、異なるFeedbackを落としません。
- ローカル下書きを優先し、他バックアップの履歴も保持。置換Importは従来どおり明示的な置換です。
- 保存容量不足を表示し、画面を閉じずバックアップを取得するよう案内。
- 履歴の日付は閲覧端末の現地時刻、保管形式はISO UTC。

## 教材を増やす

`writingTasks.js` に既存の採点サービスが対応するタスクを登録し、`writingHub.js` のentriesに表示順・タイトル・指定の書き出し・模範解答を追加します。原本の3枚の絵は `<key>-pictures.png`。実際のAI採点サービスにも同じtaskIdの登録が必要です。学校固有問題・採点契約を推測で追加しません。

将来の「書き出し」「型」の部分練習もこのHubに置く方針です。今回のモードは `full_story` のみ。部分練習は独立した stable exerciseKey と mode、採点契約を用意し、全文の80〜100語・28点の契約や履歴に混ぜません。未実装のモードのボタンは表示していません。

模範解答は非公式の一例。4つの型は内容整理の目安で、4段落の強制ではありません。提出前は型と模範解答を表示しません。提出後の修正中も学習資料は参照でき、過去の答案への評価を現在の答案に流用しません。
